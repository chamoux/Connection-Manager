### Security rules (these are review criteria)

1. **The service runs as SYSTEM.** Anything that comes from the pipe, from Steam files, from the user's profile, or from the registry under `HKEY_USERS` is untrusted.
2. **Paths.** Before the service opens, enumerates or passes to WFP any untrusted path, it must pass `SafePaths.TryLocal` (Task 2):
   - fully qualified `X:\`, on a fixed or removable drive;
   - no `\\`, `\\?\`, `\\.\`, `\??\`, or `:` after the drive letter;
   - no wildcards, no trailing dot or space in a segment;
   - no reparse point in any existing component.

   The service never writes to, deletes or runs a path it was given.
3. **Files the service writes.** It writes only inside the locked data folder (`DataFolder.EnsureSafe`) and to specific HKLM values on an allowlist.
4. **External processes** (netsh) get a full System32 path, `ArgumentList` or validated arguments, `UseShellExecute=false`, and no shell.
5. **Bounds.** Every collection that comes from outside has a cap: list lengths, string lengths, message size.
6. **Exceptions.** No exception may escape a timer, ETW or pipe callback. Log each distinct error once.
7. **Fail open.** Blocks live only in the dynamic WFP session. Persistent changes (DO policy, metered cost) are journaled before they are made, and restored at service start, at stop, and by "Restore everything".

### Task 1: Generalize WFP filters into rules (block and permit)
**Files:**
- `Core/Wfp/FilterRule.cs` (new)
- `Core/Wfp/IWfpEngine.cs`, `WfpEngine.cs`, `FilterReconciler.cs`, `FilterCondition.cs`, `WfpNative.cs`
- `Core/GameModeController.cs`
- the tests

**Design**
- `public enum RuleKind { App, Service, RemotePort, LocalPort, All }` and `public enum RuleAction { Block, Permit }`.
- `public enum RuleWeight : byte { SaverBlockAll = 2, SaverPermit = 8, GameBlock = 10, EssentialPermit = 12 }`. Loopback stays an engine-internal 15.
- `public sealed record FilterRule(RuleKind Kind, string Value, RuleAction Action, RuleWeight Weight, string Label)`.
  - Equality ignores Label and compares Value case-insensitively.
  - Port values are decimal strings `"53"`, with an optional protocol suffix `"68/udp"` (`tcp` or `udp`). Without a suffix, the rule matches any protocol.
  - `All` has Value `""`.
- `IWfpEngine.Add(FilterRule rule)` replaces `AddBlock`. It still adds one filter per layer (4 layers), or nothing.
  - Port conditions use `FWPM_CONDITION_IP_REMOTE_PORT` / `IP_LOCAL_PORT` (`FWP_UINT16`). The optional protocol uses `FWPM_CONDITION_IP_PROTOCOL` (`FWP_UINT8`: 6 = TCP, 17 = UDP) as a second condition.
  - `All` has zero conditions.
  - Get the GUIDs from the SDK headers (fwpmu.h). Extend the MSVC-verified struct layout tests in `WfpLayoutTests` if you add structs.
  - Filter display names are `"Connection Manager: block <label>"` or `"Connection Manager: allow <label>"`. The smoke test counts the block names.
- `FilterReconciler` works on `IReadOnlySet<FilterRule>`. Keep its transaction and rollback behaviour exactly.
- `GameModeController` produces Game Mode block rules: `TargetResolver` output mapped to `RuleKind.App`/`Service`, with `GameBlock` weight.
  - Expose `IReadOnlySet<FilterRule> WantedRules` / `PlanGameBlocks()` so that Task 5's Engine can combine them with Data Saver rules. `GameModeController` keeps working standalone for its existing tests.
  - Keep every existing test passing; adjust only for type renames.
- Rename `GameModeSetting` to `ModeSetting` (Auto, On, Off) with the same JSON names, and fix all references.

**Tests**
- Reconciler: block and permit rules for the same app are different rules; Label changes are not a change.
- Fake engine: records the rules.
- Integration (`[ElevatedFact]`, in `WfpEngineTests`):
  - an `All` block rule at `SaverBlockAll` makes the curl copy exit 7;
  - adding an `App` permit at `SaverPermit` for the curl copy makes it fetch (0) while block-all stays;
  - a `GameBlock` on curl beats its `SaverPermit` (exit 7).

### Task 2: SafePaths: untrusted path guard
**Files:** `Core/Paths/SafePaths.cs` (new), `Core/Blocking/TargetResolver.cs`, `Core/Blocking/PathPatterns.cs`, tests.

**API**
- `public static bool TryLocal(string? path, out string full)` applies rule 2 above:
  - normalize with `Path.GetFullPath`;
  - reject when the normalized form differs from the input in a way that hides something (a trailing dot or space segment);
  - reject when any existing prefix component has `FileAttributes.ReparsePoint` (check each prefix from the drive root down);
  - check the drive type with `DriveInfo` (Fixed or Removable only).
- `public static bool IsSafeFolderToScan(string folder)` is `TryLocal` plus "exists".

**Wiring**
- `TargetResolver` passes user blocks, catalog paths after expansion, and every enumerated file through `TryLocal` before producing a target. Rejected paths go to a `Rejected` list, logged once by the caller.
- `PathPatterns` never descends into reparse points at any level. Today `OneLevel` uses `AttributesToSkip = 0`; make it skip reparse points too, and keep its tests.

**Tests**
- UNC, `\\?\C:\x`, `\\.\pipe\x`, `C:x` (relative), `C:\a\b.exe:stream`, `C:\a\b.exe.`, wildcards, and an empty string are each rejected.
- A junction in the middle of the path is rejected; create it with `cmd /c mklink /J` and delete the junction before the temp folder.
- A normal file in temp passes.
- TargetResolver drops a user block that points through a junction.

### Task 3: IPC protocol: contracts, strict JSON, framing
**Files:** `Core/Ipc/Contracts.cs`, `IpcJson.cs`, `IpcLimits.cs`, `Framing.cs`, `StrictEnum.cs` (all new), tests.

**JSON**
- The contracts are exactly as in "Shared contracts".
- `IpcJson` is a source-generated `JsonSerializerContext` with:
  - camelCase naming, `UnmappedMemberHandling.Disallow`, `AllowDuplicateProperties = false`, `RespectNullableAnnotations`, `RespectRequiredConstructorParameters`, `MaxDepth = 8`;
  - converters `StrictEnum<T>` (string names only, no integers) for every enum.
- Add `<JsonSerializerIsReflectionEnabledByDefault>false</JsonSerializerIsReflectionEnabledByDefault>` to Core, the service and the tray. Phase 1 `SettingsStore` uses reflection JSON: give it its own source-gen context (`SettingsJson`) in this task, and keep `SettingsStore` behaviour and tests.

**Framing**
- `static async Task WriteFrameAsync(Stream s, ReadOnlyMemory<byte> json, CancellationToken ct)` writes a 4-byte little-endian length, then the payload, in a single write.
- `static async Task<byte[]?> ReadFrameAsync(Stream s, CancellationToken ct)` returns null on a clean EOF before the header. A length of 0 or more than 65 536, or EOF mid-frame, throws `InvalidDataException`.
- Helpers: `Serialize(Response)`, `TryParseRequest(byte[], out Request, out string error)`, and `ParseArgs<T>(Request)`. `ParseArgs` throws `InvalidDataException` with a short message on missing or bad args, and checks the length limits.

**Tests**
- Round trip; oversize and zero frames.
- Integer enum (`"cmd":3`) rejected; unknown property rejected; duplicate property rejected; depth 9 rejected.
- `$type` ignored or rejected.
- Bad args give a clean error; over-long paths are rejected.

### Task 4: Pipe security, server and client
**Files:** `Core/Ipc/PipeNative.cs`, `PipeServerHost.cs`, `PipeClient.cs`, `ClientIdentity.cs` (all new), tests.

Follow the research note exactly. The tested reference is `%SCRATCH%\ipcsample\Ipc.cs`: read it first and reuse it.

**PipeServerHost**
- `CreateNamedPipeW` with the spec's SDDL (owner SYSTEM):
  - `PIPE_ACCESS_DUPLEX | FILE_FLAG_OVERLAPPED`;
  - `FIRST_PIPE_INSTANCE` on the first instance;
  - `PIPE_TYPE_BYTE | PIPE_REJECT_REMOTE_CLIENTS`;
  - 8 instances, 64 KiB buffers.
- The accept loop always keeps one instance listening, so the name is never released.
- Constructor options: pipe name, SDDL override (tests only, to run without SYSTEM), and a request handler `Func<ClientIdentity, Request, CancellationToken, Task<Response>>`.
- Timeouts: 5 s for the first frame, 60 s idle unless subscribed, 5 s per write.
- **Subscribers:**
  - `Subscribe` keeps the connection open; the server pushes `Response(Id: 0, Data: StatusDto)` whenever `Publish(StatusDto)` is called.
  - Newest-only: each subscriber has a dirty flag and the latest snapshot, never a queue.
  - A heartbeat (the latest status again) goes out every 30 s.
- **Identity:** read the first frame, then `RunAsClient(() => OpenThreadToken(...))` and nothing else inside it. Query the token after reverting: user SID, session id, integrity RID, AppContainer.
  - Refuse when session == 0 (except in tests), the integrity level is below Medium, or it is an AppContainer.
  - `ClientIdentity.MayChange`: the session's `WTSConnectState == WTSActive`.
  - Log the client PID and exe path (`GetNamedPipeClientProcessId` + `NativeProcess`) on connect.

**PipeClient** (used by the tray and IpcProbe)
- Connect with `TokenImpersonationLevel.Identification`.
- Before the first write, verify the server:
  - owner == SYSTEM;
  - `GetNamedPipeServerSessionId == 0`;
  - `GetNamedPipeServerProcessId == QueryServiceStatusEx("ConnectionManager").dwProcessId`.
- `VerifyServer` can be disabled only through an `internal` test hook.
- API: `Task<Response> SendAsync(Command, object? args, CancellationToken)`, and `IAsyncEnumerable<StatusDto> SubscribeAsync(CancellationToken)`. Request ids increase.

**Tests (unit, non-elevated)**
- An in-process server with a test SDDL (owner = current user, `IU` replaced by the current user) and verification disabled:
  - request/response round trip;
  - subscribe receives a publish;
  - a slow subscriber gets only the latest;
  - an oversize frame drops the connection;
  - a client that sends nothing is dropped after the timeout (use a short test timeout).
- With verification on, the client refuses a server whose owner isn't SYSTEM. This is the squatting defence.

**Integration (`[ElevatedFact]`):** a server created with the real SDDL fails with 1307 when not run as SYSTEM. Assert the error code; it documents why SYSTEM is required.

### Task 5: The service host and Engine
**Files:**
- new project `src/ConnectionManager.Service` (WinExe → Exe, AssemblyName `ConnectionManager.Service`, `StartupHookSupport=false`, `JsonSerializerIsReflectionEnabledByDefault=false`), added to the slnx;
- `Program.cs`, `Engine.cs`, `ActiveUser.cs`, `CommandHandler.cs`;
- `Core/Steam/SteamLibraries.cs`;
- a new test project or folder. Engine logic lives in Core, under `Core/Engine/`, so the existing test project covers it.

**Program**
- `Host.CreateEmptyApplicationBuilder(new() { ContentRootPath = AppContext.BaseDirectory })` + `AddWindowsService(o => o.ServiceName = "ConnectionManager")` + a hosted worker. It runs as a console app when not under the SCM; the smoke test uses that.
- At start:
  - check `DataFolder.EnsureSafe`; on failure, write to the Windows Application event log (source "ConnectionManager", registered by the installer, with a fallback to stderr) and exit 1;
  - create the FileLog, load settings, set manual On back to Auto for both modes and save;
  - run the Restore pass (journal) before anything else.
- A fatal error calls `Environment.Exit(1)`, so the SCM restarts the service.

**Engine** (Core, single-threaded)
- One loop: a `Channel<Func<Task>>` of work items plus a 2 s tick, from a `TimeProvider` (testable).
- It owns:
  - `GameModeController` (rules);
  - placeholders for `DataSaverPlanner`, `DoCapManager`, `WifiTuner`, `TrafficMeter` and `ReportStore` (interfaces, wired by later tasks; no-op implementations for now);
  - one `FilterReconciler` that applies the union of Game Mode and Data Saver rules each tick when anything changed (or every 60 s while active, as Phase 1 does), with Phase 1's back-off semantics;
  - `SettingsStore`.
- Each tick builds a `StatusDto` (Version++ when anything changed) and calls `Publish`.
- `HandleAsync(ClientIdentity, Request)` posts to the loop and awaits a `TaskCompletionSource`.
  - **Validation:** `MayChange` for every command except GetStatus, Subscribe, GetUsage and GetReports; args via `ParseArgs`; paths via `SafePaths.TryLocal`; options ranges; hotkey parse; list caps.
  - **Save** the settings after each change. A failed save returns Ok with a warning in Problems; the change is still applied in memory.
  - **Errors** come back as `Response(Ok: false, Error: <short plain message>)`, never stack traces.
  - `AddBlock` and `AllowApp` refuse protected paths, using Phase 1's `GameModeController.IsProtected` extended to Data Saver.
- **Phase 1 tray logic moves here:** `TrayContext.ChangeSettings` semantics, AddGame/MarkNotAGame and so on.

**ActiveUser**
- `WTSGetActiveConsoleSessionId` → `WTSQueryUserToken` → SID plus `SHGetKnownFolderPath(LocalAppData / RoamingAppData / Profile, token)`.
- `ExpandUserEnv(string)` maps `%LOCALAPPDATA%`, `%APPDATA%` and `%USERPROFILE%` to that user's folders; other variables go through `Environment.ExpandEnvironmentVariables`. With no active user, the patterns that need user variables are skipped.

**Steam path:** `HKLM\SOFTWARE\WOW6432Node\Valve\Steam\InstallPath` first, then `HKEY_USERS\<active sid>\Software\Valve\Steam\SteamPath`. Treat both as untrusted, so `SafePaths` applies before any file read. Cap `libraryfolders.vdf` reads at 1 MB.

**Tests (unit, Core)**
- Engine with fakes (FakeTimeProvider, fake engine, fake process source):
  - SetGameMode On blocks and pushes status;
  - a command from a non-active session is refused;
  - a bad path is refused;
  - options out of range are refused;
  - manual On resets at startup;
  - the union of rules is applied in one reconcile.

### Task 8: NetworkWatcher and hotspot classifier
**Files:** `Core/Network/NetworkSnapshot.cs`, `HotspotClassifier.cs`, `NetworkWatcher.cs`, `NlmInterop.cs` (all new), tests.

**NetworkSnapshot** (record): `Kind` (Ethernet / Wifi / None), `AdapterId`, `Name` (NLM network name), `Gateways`, `Cost` (Unknown / Unrestricted / Fixed / Variable), `IfIndex`.

**NetworkWatcher.Read()**
- `NetworkInterface.GetAllNetworkInterfaces()`: up, non-loopback, non-tunnel, with an IPv4/IPv6 default gateway.
- Ethernet wins if any is up with a gateway. Otherwise use Wi-Fi.
- NLM over COM gives the name and the per-connection cost, matching `INetworkConnection.GetAdapterId()` to `NetworkInterface.Id`. Use the typed interfaces from the Wi-Fi research note.
- `GetNetworkConnectivityHint` is the cost fallback.
- Changes: `NetworkChange.NetworkAddressChanged` and `NetworkAvailabilityChanged` set a dirty flag, and the Engine re-reads on a dirty flag or every 15 s.
- No exceptions out: a COM failure returns `Cost = Unknown` and `Name = null`.

**HotspotClassifier.Classify(snapshot, hotspotNames, autoOnMeteredWifi) → (bool IsHotspot, string Reason)**. It is pure:
- Ethernet or None → false ("Ethernet" / "No network").
- Wi-Fi:
  - the name is in the list (case-sensitive) → "Your hotspot";
  - a gateway is 172.20.10.1 → "iPhone hotspot";
  - `autoOnMeteredWifi` and the cost is Fixed or Variable → "Metered Wi-Fi";

### Task 10: Delivery Optimization caps with a journal
**Files:** `Core/Caps/IRegistryStore.cs` (interface + real HKLM implementation), `PolicyJournal.cs`, `DoCapManager.cs` (new), Engine wiring, tests.

**Values:** `HKLM\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization`, `DOMaxBackgroundDownloadBandwidth` and `DOMaxForegroundDownloadBandwidth` (DWORD, KB/s, at least 1). Use exactly these names and nothing else: an allowlist in code.

**Journal** (`<data>\journal.json`, written atomically). Per value it records: key, name, keyExisted, priorExists, priorKind, priorData, writtenData.
- **Apply:**
  1. If a journal exists, Restore first.
  2. Skip a value that already exists (a foreign policy) and log it once.
  3. Write the journal, then the values.
  4. Call `RefreshPolicyEx(true, RP_FORCE)` (userenv.dll).
- **Restore:**
  - current == written → put back the prior value (or delete it);
  - current == prior → nothing;
  - anything else → leave it and log.
  - Delete the keys we created only if they are empty. Refresh the policy, then delete the journal last. Restore is idempotent.
  - Only allowlisted key and value names are ever restored, even if the journal says otherwise.

**When:** caps are wanted when `SaverActive && AllowWindowsDownloads`. Apply on the false→true edge, restore on true→false, at service start (before anything), at service stop, and on RestoreEverything. Changing the cap value while active means Restore, then Apply.

**Tests (fake registry):**
- absent → apply → restore deletes the value and the created key;
- a foreign value is skipped;
- a crash after the journal write but before the registry write restores cleanly;
- a value changed by someone else is left alone;
- a tampered journal naming another value is ignored.

**Integration (`[ElevatedFact]`):** a real round trip on HKLM. Assert the final state equals the initial state.
